# File Ownership and Precedence

Which files you can edit, what overwrites them, and which value wins when copies disagree.

## Who owns each file
| File / area | Edit it? | Overwritten by | Notes |
|---|---|---|---|
| `src/main/java/frc/powerlib/**` | **No** | every library install/update | Changes are lost. Change them in Robot-Library instead. |
| `frc/robot/**` template files (`RobotContainer`, `StateMachine`, `Swerve`, `Vision`, `PowerDashboard`, `constants/*`…) | Yes, after first install | first install only (with `.powerlib.bak` backup) | Later installs write `X.template` beside your file; merge by hand. Old `RobotContainer`/`PowerDashboard` versions are force-replaced (see [Installer Flow](../02-Install-and-Update/Installer%20Flow.md)). |
| `autos/RobotAutos.java` | Yes | never | Create-only |
| `constants/<Subsystem>Constants.java` (generated) | **Only inside the custom block** | every Update Code | Header says "Generated by PowerLib subsystem tool". |
| `constants/SwerveConstants.java` | **Only inside the custom block** | every Update Code (from the JSON `swerve` section) | |
| `constants/GeneratedTunableConstants.java` | **No** | every Update Code | |
| `characterization/*Characterization.java` | **No** | every Update Code | |
| `Constants.java` | Yes, outside the generated markers | generated block on Update Code | Unmarked aliases pointing at generated files are removed. |
| `StateMachine.java` | Yes, outside the generated markers | generated block on Update Code | Migrations may add missing telemetry/tuning support. |
| `PowerDashboard.java` | Yes, carefully | characterization block + named library methods on Update Code | `Ensure-*` migrations replace specific methods and keep your other members. |
| `power-tool/generated/*.json` | Through Power Tool (or by hand) | never by updates | **Source of truth** for generated Java |
| `power-tool/dashboard/**` | Yes | never | Team-owned Drive tab |
| `power-tool/src`, `electron`, `package.json`… | **No** | every Update Power Tool | |
| `power-tool/scripts/**` | No | Update Power Tool / install | |
| `skills/**` | No | install / Update Power Tool | |

## The custom constants block
```java
  // POWERLIB CUSTOM CONSTANTS START - DO NOT DELETE
  public static final double INTAKE_SPEED_RPS = 40.0;
  // POWERLIB CUSTOM CONSTANTS END - DO NOT DELETE
```
- **Before** the file has an entry in `powerlib-constants.json`:
  - The block is copied by subsystem **id** from the old file into the regenerated one, so renames keep it.
  - On the first Update Code (or the first save in Power Tool), its constants are **imported** into `powerlib-constants.json`.
- **After** that, the block is **regenerated from the JSON** (`custom: true` rows) on every Update Code. Hand edits to the Java block are overwritten, and so are newly added Java lines.
  - Change existing values in Power Tool (Robot tab drawer).
  - **Add** new constants as rows in `powerlib-constants.json`. The drawer doesn't add constants.
- Numeric custom constants become `@TunableConstant public static volatile`, which makes them live-tunable as `Custom/<NAME>`.
- Don't delete the markers. The generator and Power Tool both need them.

## Which value wins
From strongest at runtime to the long-term source of truth:

| Layer | Lifetime | Wins over | Loses to |
|---|---|---|---|
| **Live tuning value** (NT, tuning ON) | until robot restart | Java defaults at runtime | a restart; turning tuning OFF freezes the last applied value |
| **Java constants** (compiled) | until next deploy | — | the next Update Code + deploy |
| **`powerlib-constants.json`** | permanent | Java constants (Update Code rewrites the Java) | — |
| **`powerlib-subsystems.json`** | permanent | generated subsystem constants and `SwerveConstants` | — |

Rules of thumb:
- **Java vs JSON:** once a constants file has a JSON entry, **the JSON wins** on the next Update Code, so a hand edit to a generated value is silently reverted. Exception: constants files that have *no* JSON entry yet are imported from Java the first time.
- **Subsystem gains:** `powerlib-subsystems.json` wins. `powerlib-constants.json` holds only *custom* constants for subsystem files.
- **Swerve:** built-in defaults (`DRIVER_*`, `REQUESTS_*`, `DRIVE_TO_POINT_*`, `HEADING_K*`) come from `powerlib-subsystems.json` → `swerve`. Custom Swerve constants come from `powerlib-constants.json`.
- **Live vs saved:** live edits never write JSON on their own. Use **Save Tuned Values** to copy them to JSON, then Update Code.
- **Invalid live values** are rejected: the mechanism keeps its last accepted value, and a `@TunableConstant` reverts to its startup default. A warning appears on the Driver Station.
